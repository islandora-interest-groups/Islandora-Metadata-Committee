### Notes:

* Review of questions in Slack
  * [Thursday May 14 - Joe Corall](https://islandora.slack.com/archives/CM9CVQWJ0/p1778776595622859): Should we make a separate "Qualified Dublin Core"(1) "OAI-PMH Format"(2) so that we can include dc:extent per a harvester's request?
    * (1) - do you mean Qualified Dublin Core (superceded by DC Terms) or DC Terms? We assume the latter; lots of people use them interchangeably. Yes, DC Terms sounds like a good idea.
    * (2) - "Format" doesn't line up with the options in the interface, so we're not quite sure what's meant. A new (4th) option in the "Metadata Mappings" list (which currently has oai_raw, oai_dc, and mods)? Or, a new entry in the dropdown under "oai_dc" (which currently lists OAI Dublin Core (Metatag) and OAI Dublin Core (RDF Mapping))? We think that the first one would be better (like the way that the OAI PMH LAC module makes a new Metadata Mapping for "oai_lac") because then you could still provide endpoints for harvesters who don't want / can't deal with the extra stuff.
  * [Friday, June 12 - Natalie Baur](https://islandora.slack.com/archives/CM9CVQWJ0/p1781292475675509): Can we create a new content model for archival series? What about migration / data modeling?
    * Comments from Mark Jordan and kayakr indicate it's good and possible with the existing membership model. We agree.
    * We talked a lot about Member Of and how it really serves as an all-purpose membership relation.
    * Rosie mentioned that having multiple parents is a thing that's easily forgotten/lost during a migration.
    * Katie showed an example of ArchivesSpace and how it organizes content. It has a lovely sidebar hierarchy tree that lets you navigate through the collection even when you're on an object.
      * Rosie though this was imminently doable. 
    * Mike showed an example of a finding aid that was done in Islandora, with a sidebar panel that slides out with a table of contents (since the finding aid is very long).
